```markdown
## 核心原则（常驻速览，概览类问题读到这里即可回答）

1. 图像管外观与姿态，文字管动作与声音：可见信息用参考图，不可见信息才写文字
2. 提示词越复杂模型越跑偏，只写这次要发生的变化
3. 同一份提示词反复不对，说明通道选错了，不是措辞问题
4. 一次只解决一个问题：先静态定构图，再动态定运动
5. 不整段重跑，从已有结果里挑可用部分继续推进
```

```
## 四、可提炼的方法单元（18 条）

### A. 参考图优先原则（最高价值）

**1. 提示词失效时加图像参考**
同一份提示词，加一张参考图，模型立刻"听话"。这是全课反复出现的核心手法：
- 白板/熟脸没有填进去 → 加参考图
- 表情不对 → 加表情参考图
- 插入画面没感觉 → 加插入参考图
- 口交跑了方向 → 加参考图
- 模型跑不出某种姿势 → 直接丢图让它参考

**2. 提示词极简原则**
"提示词其实不需要太多、太复杂。太复杂的话，模型可能会吃你一半。"
- 皮肤质感：一句"全身皮肤有水光"就够
- 反面：写太多形容词，模型跑偏
- 但音效/节奏这类必须写清（"有节奏的插入""汗水""叫声"）

**3. 姿势图前置**
反复抽不到卡时，先做静态姿势图，再拿姿势图去跑视频。
- 好处：构图和手部关系先锁死
- 效果：一卡就能出来，不用反复抽卡

**4. 复杂设定先做主体图**
剧本复杂（捆绑+口塞+多部位固定）时，模型怎么聊都生不出来。
做法：先做一张主体图，以它为基础再生成。怕穿帮就把眼睛遮住、形象不变。
"这样可以省很多次抽卡。"

### B. 视频参考与串脸

**5. 视频参考会带错角色特征**
用视频参考时，容易把参考里角色的尺寸/特征带进你的角色（"上集凶那么小，这集这么大"）。

**6. 白膜 / 深度图解法**
用白膜（深度图）替代真人参考，只传递动作不传递外观。
缺点：麻烦、要装。
替代：不想用白膜的，用"锁定类"参考。

**7. 四锁原则**
锁脸、锁身材、锁发型、锁位置。
"参考的时候千万不要 30 秒这样丢，就一个镜头就行了。"

**8. 想更真：男主不参考**
追求极致真实时，男主干脆不用参考，只用前几秒。
"后面的人物肯定是不对的，你把想用的那几秒截下来就够了。"

### C. 多人场景

**9. 多人必须 16:9**
6P 这类场景，9:16 画面太窄，人物堆不下。要改 16:9。

**10. 人物"写死"**
每个人物给 ID，明确每个站位，写清楚。不需要更多复杂描述。

**11. 九宫格只做背景**
九宫格/群像图适合运动会、群架这类场景，但只当背景模板用，主角仍要单独丢参考图。
"直接九宫格出视频，肯定不行。"

### D. 衔接与补救

**12. 尾帧接首帧 + 资产不能丢**
下一卡除了尾帧，**人物资产必须一起放进去**，否则人物会变。

**13. 抽卡补救法**
30 秒里总有几秒不穿帮。把那一帧截图下来，用它去生成下一段，而不是整段重来。

**14. 音效不参考音频**
参考视频的音频（外语、环境音）要去掉，用提示词写：叫声、呼吸声、身体起伏、水声、摩擦声、不要叠音。

**15. 插入画面单独出**
插入那一段看起来假，就单独剪出来出一个 7 秒的反复抽卡，后面的保留。

### E. 判断与市场

**16. 题材判断**
- 家庭伦理最热，但做不出来的也多
- 女性向是空白市场，需求真实存在（有人愿意定制付费）
- 猎奇能吸引人，但不能太恐怖

**17. 人物资产要有"缺点"**
"她不漂亮，但她身材好"——反而是卖点。
主角要有性格（糯糯的、胆子大），观众才觉得像真人。
配角可以当"总肥肥大"那种，主角不要。

**18. 色情比例约 30%**
第一集带色感但不纯肉；核心设定、世界观要先放前面；真正到肉的地方占三成。

| 前戏 / 插入 | 生成时的两个阶段，插入单独处理 |

## 六、批判与局限

**成立的部分**
- "提示词搞不定就加参考图"是全课最有价值的判断，且可验证
- 四锁、尾帧+资产、抽卡补救，都是可复现的工程做法
- "提示词越复杂模型越跑偏"符合实际观察

**局限**
1. **全部是口述经验，零数据**：没有成功率、返工次数、耗时统计
2. **强依赖特定工具链**：Grok + 特定生图/生视频平台，换工具需重验
3. **无失败归因体系**：知道"加参考图有用"，但没解释什么时候加、加几张、加什么类型的图最有效
4. **质量判定主观**："效果好""像真人"没有可量化标准
5. **部分内容属平台规避技巧**（未成年/版权），不适合作为方法论沉淀
6. **口语冗余高**：21,000 字里约三成是重复、口头禅、现场噪音
```

```markdown
| 丢参考 / 垫图 | 把图片或视频加入生成节点作为参考，替代或补充文字描述 |
| 听话 | 模型按预期执行了提示词要求 |
| 抽卡 | 反复生成直到出现可用结果 |
| 穿帮 | 画面出现不符合设定的错误：人物变形、道具消失、空间错乱、尺寸不一致 |
| 白膜 / 深度图 | 只保留动作轮廓、不传递外观的参考素材 |
| 四锁 | 锁脸、锁身材、锁发型、锁位置（原文称四锁，实列五项） |
| 写死 | 用 ID 和明确站位把人物固定住，不给模型自由发挥空间 |
| 主体图 | 把复杂设定先在一张图上固定的基础图 |
| 姿势图 | 静态关键姿态参考图，用于锁定构图与手部/道具关系 |
| 尾帧 / 首帧 | 前一卡最后一帧 / 下一卡第一帧 |
| 母提示词 | 对话前发给模型的工作要求，规定身份、任务、规则、风格、格式 |
| 资产图 | 生成前准备的人物、服装、道具、场景参考图；人物与物品用空白背景 |
| 分镜卡 | 一次生成承载的一段连续动作；镜头管"看什么"，卡管"一次生成多少" |
| 九宫格 / 群像图 | 一次生成多人物或多视角的构图，只适合作背景模板 |
| 前戏 / 插入 | 生成流程的两类镜头阶段；插入难度高，常需单独出、单独抽卡 |
```

## 六、01 提示词失效时转用图像参考（critical）

```markdown
# 提示词失效时转用图像参考

## R · 原文摘录
> "一模一样的提示词，那也是要去填，但是我去加了个什么呢，我加了一张参考图……你丢了这个参考图之后，模型就开始听话了。"
> "市面上很多很多种问题，比如模型不听话的，参考图可以解决你。"

## I · 我的理解
模型对文字描述的理解是有上限的。当同一份提示词反复生成都不对时，问题不在措辞，而在**通道选择错了**：这个信息本来就该用图像表达，而不是文字。此时继续加长提示词只会让模型更混乱（见 prompt-minimalism）。正确动作是切换到图像通道——加一张参考图。

## A1 · 书中案例
- 白板/熟脸没填：提示词写了"在女主上面去填"，结果没执行；加 18 秒参考图后立刻执行
- 口交方向跑错：要口交，模型跑到下面；丢参考图纠正
- 插入画面没感觉：加插入参考图后，"虽然手臂挡住，但效果比第一个要好"
- 表情/汗水缺失：加表情参考

## A2 · 与相邻能力的区分
- `prompt-minimalism`：讲"提示词该写多短"，本条讲"什么时候改用图"
- `pose-first`：姿势图是生成一张新的参考图；本条是找现成的图

## E · 执行方式
**输入**：一份已写好但不生效的提示词 + 一个不符合预期的生成结果

**步骤**
1. 确认提示词本身没有逻辑错误（参照、人物、动作都写对了）
2. 判断失效类型：外观/位置/姿态类 → 适合用图；节奏/声音/动作过程类 → 不适合，继续用文字
3. 找一张符合预期的参考图（网络素材即可）
4. 保持提示词不变，只加参考图
5. 重新生成

**输出**：一份"提示词 + 参考图"的节点配置

**完成标准**：同等提示词下，效果明显优于无参考图版本

## B · 边界
- 只适用于**可见信息**（外观、姿态、位置、朝向）。声音、节奏、情绪强度这类不可见信息用图无效
- 参考图会带入其自身特征，可能污染角色（见 video-ref-guard）
- 原文未说明参考图数量上限与优先级
```

## 七、02 提示词精简原则（high）

```markdown
# 提示词精简原则

## R · 原文摘录
> "提示词，其实不需要太多，太复杂。太复杂的话，模型的会只可能会吃你一半。"
> "你不要写很多，其实就是很简单的，你看，全身是皮肤有水光，就够了。你太复杂，反而模型会跑掉、跑乱。"

## I · 我的理解
提示词的作用是**指示这次要发生什么变化**，不是替代参考图去描述外观。写太多形容词会稀释关键指令，模型只抓到一部分。正确做法是：外观交给图，文字只写动作、顺序、节奏、声音。

## A1 · 书中案例
- 皮肤质感：只需"全身皮肤有水光"一句，写多了反而跑
- 反面示范：堆叠大量描述 → "模型会吃你一半"
- 例外：节奏类的必须写清（"有节奏的插入""汗水""叫声"）

## A2 · 与相邻能力的区分
- `resolve-by-reference`：本条管"该写多短"，那条管"什么时候完全不用文字改用图"
- 两条互补：精简掉的外观描述，正好由参考图承担

## E · 执行方式
**输入**：一份初稿提示词

**步骤**
1. 划出所有"描述外观"的词（脸型、身材、材质、颜色、服装细节）
2. 这些删掉，改为参考图
3. 保留：主体是谁、当前状态、动作顺序、镜头看到什么、声音
4. 检查是否有互相冲突的要求（如"原地站定"+"走到门口"）
5. 提交

**输出**：一份只含"变化"的短提示词 + 配套参考图

**完成标准**：提示词能在 3–5 句内读完；每条都在描述"这次怎么动"，而非"长什么样"

## B · 边界
- 节奏、声音、动作衔接**不能**省，省了会出错
- 多人场景的人物归属必须写清，不能靠精简
```

## 八、03 静态姿势图前置（high）

```markdown
# 静态姿势图前置

## R · 原文摘录
> "先做一张这种类型的姿势图，然后用这种姿势图去跑，她给观众的一种看法的话，就会比较好，我这没抽卡，好的，就是一卡。"

## I · 我的理解
视频生成要同时解决"构图"和"运动"两件事，复杂度高，所以反复抽卡。拆开做：先用图像把构图、手部位置、道具朝向固定死，再让视频只负责"从这个状态开始运动"。一次只解决一个问题。

## A1 · 书中案例
- 女性自慰姿势：直接跑视频会变形、要抽卡；先做静态姿势图后，一卡出结果
- 拧门把手类动作：先确定手与把手的接触位置，再描述转动

## A2 · 与相邻能力的区分
- `complex-setup-base-image`：主体图解决"多约束放不进一句话"；姿势图解决"单姿势反复出不来"
- `resolve-by-reference`：用现成图；本条是**生成**一张图

## E · 执行方式
**输入**：一个反复失败的镜头描述

**步骤**
1. 停止追加动作词
2. 先生成静态图，只描述：谁、在哪里、手接触哪里、道具朝向
3. 检查静态关系是否正确（人物没变形、接触点对）
4. 把这张图作为首帧或参考，再描述接下来的运动
5. 生成视频

**输出**：一张姿势参考图 + 一段视频

**完成标准**：视频首帧与姿势图一致；一次生成即可用，无需大量抽卡

## B · 边界
- 适用于同场景连续动作；换场景需重新做
- 姿势图本身出错时先修图，不要带错进视频
```

## 九、04 视频参考防串脸（critical）

```markdown
# 视频参考防串脸

## R · 原文摘录
> "你在视频里面参考的时候，它很容易把这个角色带入到这个角色里面来，所以就会出现这种比较大的问题，这观众一看你这太假了，你上集它凶那么小，这集这么大。"
> "锁定……锁脸、加锁身材、锁状态、锁发型、锁位置。参考的时候千万不要 30 秒的这样丢，就一个镜头就行了。"

## I · 我的理解
视频参考传递的是**动作**，但模型分不清哪些特征该继承、哪些不该。结果是参考视频里的身体尺寸、脸型被一起搬进你的角色。解决方向有三个：降低参考的信息量（白膜/深度图）、用约束把不该变的锁住、缩小参考范围。

## A1 · 书中案例
- 角色尺寸错乱："上集凶那么小，这集这么大"，观众一眼看出假，还浪费积分
- 解法一：白膜（深度图）——只传动作不传外观
- 解法二：四锁——锁脸、锁身材、锁发型、锁位置
- 解法三：只参考前面几秒

## A2 · 与相邻能力的区分
- `multi-person-layout`：解决多人堆不下；本条解决单人特征被污染
- `tail-frame-handoff`：用自己上一卡的帧；本条用外部参考视频

## E · 执行方式
**输入**：一个参考视频 + 自己的角色资产图

**步骤**
1. 检查参考视频里是否有与你角色不同的外观特征（尺寸、脸、发型）
2. 有则三选一：
   - 转白膜/深度图（只留动作）
   - 加约束：锁脸、锁身材、锁发型、锁位置
   - 只截取单镜头，不丢整段
3. 生成
4. 对照资产图检查：脸、发型、尺寸是否一致

**输出**：一个带约束的参考配置

**完成标准**：生成结果的角色特征与资产图一致，不因参考视频而改变

## B · 边界
- 原文称"四锁"但实际列了五项，且**未说明用什么工具或参数实现**——只能作为约束维度清单使用，不能承诺具体手段
- 白膜的制作方法原文未讲
- 追求极致真实时可以反向操作：干脆不用参考，只用前几秒（见 P5）
```

## 十、05 多人场景重构（high）

```markdown
# 多人场景重构

## R · 原文摘录
> "6P 那你就不能 9 比 16 了……因为它的整个镜头只有这么长，你哪怕 9 比 16……那人物都堆不了那么多。"
> "6P 的人物要把写死……ID 出来，然后每个人在哪个站位，然后把它清楚，其实就够了。"

## I · 我的理解
多人场景的失败大多来自两个约束冲突：竖屏放不下，和人物太多导致模型不知道该按谁的描述走。解法是把"构图"和"人物身份"分别用画幅和 ID 解决，不再依赖文字描述。

## A1 · 书中案例
- 6P 场景：9:16 堆不下 → 改 16:9
- 人物"写死"：每人给 ID + 明确站位
- 学员实况：做到六批，人物穿模、站位穿帮

## A2 · 与相邻能力的区分
- `group-shot-background`：九宫格只当背景；本条是完整的多人生成方案
- `video-ref-guard`：单人特征污染；本条的难点是多人调度

## E · 执行方式
**输入**：一个需要 N 人同框的镜头

**步骤**
1. N ≥ 4 时，画幅改 16:9
2. 为每个出场人物分配 ID
3. 明确每人站位（画面左右、前后、朝向）
4. 逐人绑定资产参考
5. 生成前核对：人数、ID 与站位一一对应

**输出**：一份多人场景配置

**完成标准**：生成结果中每个人物的身份、位置与配置一致，无穿模

## B · 边界
- 16:9 与竖屏成片的转换原文未讲
- 人物越多，越需要接受"只能用几秒"（见 P5）
```

## 十一、06 尾帧衔接（high）

```markdown
# 尾帧衔接

## R · 原文摘录
> "把他最后一针尾帧扣出来，然后放在这里面来……但是你的人物资产还需要放进去，人物资产一定要放进去。"

## I · 我的理解
两卡接不上，是因为下一卡从零开始生成，模型不知道上一卡结束在什么状态。把尾帧作为下一卡首帧，等于把状态直接喂给模型。但只给画面不够——模型还需要知道这张脸是谁，所以人物资产必须同时在场。

## A1 · 书中案例
- 20 秒不够 30 秒时的衔接：把尾帧接上去，人物资产一起放
- 学员普遍问题：只放尾帧，人物就变了

## A2 · 与相邻能力的区分
- `salvage-frame`：从废片里挑可用帧救回来；本条是正常衔接
- `video-ref-guard`：防外部参考污染；本条用自己的帧

## E · 执行方式
**输入**：前一卡的可用结尾 + 下一卡的动作描述

**步骤**
1. 从前一卡导出最后一个清晰、状态正确的帧
2. 检查该帧：人物位置、服装、道具、视线、光线是否正常
3. 作为下一卡首帧输入
4. **同时加入人物资产参考**
5. 描述从当前状态继续的动作
6. 生成后从接缝前几秒回放，裁掉重复停顿

**输出**：下一卡视频

**完成标准**：接缝处人物不变、动作连续、无重复帧停顿

## B · 边界
- 尾帧已变形时先修或换一帧，不要把错误带进下一卡
- 换场景、换机位、时间跳跃时不适用
```

## 十二、07 抽卡补救：截可用帧（high）

```markdown
# 抽卡补救：截可用帧

## R · 原文摘录
> "他总有不穿帮的镜头，你把那一针截图截下来……然后再用那一针去生，你不要直接一次性 30 秒的模型，他也达不到你那么大的要求。"

## I · 我的理解
30 秒的生成里几乎不可能全程正确。整段重跑成本高、收益低。更经济的是把已有结果当成"素材矿"——从中挑出正确的那一帧，作为新起点继续推进。

## A1 · 书中案例
- 六人站位穿帮：用火车人固定后仍有穿帮；改为从已生成的一卡里截不穿帮的那一帧再补镜头
- 时间点提示：可能在 3 秒、8 秒、15 秒处

## A2 · 与相邻能力的区分
- `tail-frame-handoff`：正常衔接用尾帧；本条是从**废片**里捞可用帧
- 两者形态相同（都是拿一帧当首帧），触发条件不同

## E · 执行方式
**输入**：一个部分穿帮的生成结果

**步骤**
1. 逐段查看，定位不穿帮的区间
2. 截取该帧（分辨率要够）
3. 把它作为下一段的首帧
4. 补齐需要的前后镜头
5. 后期把可用部分拼接

**输出**：若干可用片段 + 新的生成起点

**完成标准**：最终成片不含穿帮；没有整段重跑

## B · 边界
- 截图分辨率不足时不可用
- 只适合"局部错"，主体全错时仍需重做
```

## 十三、08 复杂设定先做主体图（medium）

```markdown

## R · 原文摘录

完成标准：后续生成不再需要重复描述这些约束

## B · 边界

```

## 十四、09 九宫格背景 + 单独主角（medium）

```markdown
## R · 原文摘录
```

## 十五、10 插入画面单独生成再拼（medium）

```markdown
# 插入画面单独生成再拼

## R · 原文摘录
> "你可以把前面这一节把它剪掉，单独去出个 7 秒钟的插入的，可以反复去抽卡都行，后面的这一段就保留下来。"

## I
插入类镜头难度最高，和前后剧情的生成条件冲突。把它单独拆出来反复抽卡，前后段保持原样，后期拼接——牺牲一点连贯性，换来画面质量。

## E · 执行

步骤：1) 识别难点段 2) 单独剪出生成 3) 反复抽卡至满意 4) 前后段保留 5) 后期拼接

完成标准：难点段质量达标，接缝可接受

## B · 边界
拆分会产生接缝，需要更仔细的衔接处理
```

## 十六、11 音效替代：去掉参考音频自己写（medium）

```markdown
# 音效替代：去掉参考音频自己写

## R · 原文摘录
> "你把他这个音频去掉……你那些叫声，你可以在提示词里面去写，你去写他怎么叫的、怎么喊的……呼吸声、身体的起伏，其实就是这几句话，就能解决很多问题了。"

## I
参考视频的音频是别人的（外语、环境噪音），直接用会出错。声音属于不可见信息，用图无效，只能靠文字描述 + 后期补。

## A1
- 参考视频讲日语 → 去掉音频
- 提示词写：叫声、呼吸声、身体起伏、水声、摩擦声
- 明确"不要叠音"

## A2
- `prompt-minimalism` 说提示词要短，但声音类是**例外**，必须写

## E · 执行
输入：带参考视频的生成任务
步骤：1) 剥离参考音频 2) 提示词补声音要素 3) 生成 4) 后期加音效
输出：无错误音频的视频 + 后期音轨
完成标准：无外语残留、无叠音，声音与动作同步

## B · 边界
生成模型对声音的控制有限，关键音效仍需后期
```

## 十七、12 上下文窗口重置（medium）

```markdown
# 上下文窗口重置

## R · 原文摘录
> "有时候一个窗口使用太长了，它肯定会跟你漏掉很多东西，我建议的话，你是新开个窗口，然后从你第一个窗口怎么训练它的，重复再训那一次就可以了。"

## I
长对话会让模型变慢、失忆、敷衍。这不是功能缺陷而是必然——上下文越长，关键信息越被稀释。解法不是"提醒它"，而是重开窗口、重放母提示词。

## A1
- 学员问：Grok 为什么秒出、不思考 → 窗口用久了
- 对策：新开窗口，重新丢母提示词校准

## A2
- 与教材的"新剧新对话"同源，本条侧重性能退化而非项目隔离

## E · 执行
输入：一个明显退化的工作窗口
步骤：1) 判断是否因上下文过长 2) 导出当前进展 3) 新开窗口 4) 重放母提示词 5) 只带必要上下文
输出：一个干净的新窗口
完成标准：响应速度恢复，不再漏信息

## B · 边界
原文未给"用多久该换"的阈值
```

## 十八、13 封面参考法（low）

```markdown
# 封面参考法

## R · 原文摘录
> "你去找一个封面去……然后你让不管是让 GPT 啊，还是让 Grok，你让她去参考这个封面，然后把你的人物外观剧情，把你的名字写上去。"

## I
封面本质是"排版 + 人物 + 文字"。找一张现成封面当参考，比自己描述版式高效得多。多人封面容易错乱，所以先用草图把站位画出来。

## A1
- 单人：找现成封面 → 发给模型 → 上传自己人物 → 改色
- 多人（4–5 人）：先用美图秀秀画站位草图（谁在哪、什么姿势），再丢给模型

## A2
- `resolve-by-reference` 是通用原则；本条是它在封面场景的具体应用

## E · 执行
输入：剧名、人物资产、剧情要点
步骤：1) 找参考封面 2) 多人先画站位草图 3) 指定参考 4) 要求带上人物与文字 5) 校验
输出：一张封面
完成标准：人物不错乱、文字无错、版式成立

## B · 边界
参考他人封面涉及版权，需自行判断使用范围
```
